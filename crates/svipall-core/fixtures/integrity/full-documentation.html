Configuring the retry policy

The client retries a request when the response is a connection error or one of the status codes listed in retry_on. Every other response, including a 400, is returned to the caller unchanged: retrying a request the server has understood and rejected only wastes the quota.

Backoff

Delays grow exponentially from base_delay and are capped at max_delay. Jitter is applied by default, because a fleet that retries on the same schedule turns one outage into a thundering herd when the service comes back. Set jitter = false only when you are reproducing a timing bug and need the sequence to be deterministic.

Budgets

A retry budget bounds the additional load retries may add, expressed as a fraction of the original request rate. When the budget is exhausted the client stops retrying until it refills, which keeps a failing dependency from being retried into the ground.
